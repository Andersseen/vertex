# 0.14 — Test, build, and publish projects

Status: pending. Depends on 0.13, build artifacts from 0.10, and transport decisions
from 0.12. Contracts: C6/C9/C12. Cloudflare is the only deployment platform.

**User outcome:** validate a project and publish a known static artifact from Vertex,
including clear diagnosis when a test, build, or network request fails.

## Ordered tasks

### V14-01 — Project verification workflow

- Paths: task panel/commands, diagnostics output, project template scripts.
- Provide discoverable test, typecheck, lint, and build actions for scripts actually
  present. Reuse 0.9 processes, trust, cancellation, and snapshot identities.
- Certify one pinned test-runner setup in F03, with structured results when available
  and honest log/exit-code fallback for other scripts. Do not report zero tests as success
  when no test task exists. Cached results become stale after relevant edits.
- **Acceptance:** pass/fail/cancel/watch are distinguishable; failing test opens useful
  source/log context. A nonexistent script yields guidance, not an invented pass.

### V14-02 — Prepare and inspect a publishable artifact

- Paths: build output manifest, `runtime/src/deploy/adapters/base.ts`, publish UI.
- Require a successful source-associated build and explicit output directory. Show
  destination, file count/size, build identity, and any newer edits before publication.
- Exclude project credentials, `.git`, dependency trees, and unintended source files.
  Preserve binary hashes; define sourcemap inclusion as an explicit artifact policy.
- **Acceptance:** stale/failed builds cannot be presented as current successful builds;
  workspace-root misconfiguration is rejected. Exported artifact runs independently.

### V14-03 — Credential-safe Cloudflare connection

- Paths: deployment credential provider, existing Pages adapter, controlled gateway
  routes only if validated as necessary, and setup documentation.
- Use user-owned account/project credentials with appropriate permissions. Keep tokens
  out of browser persistence, runtime processes, logs, preview, and artifacts. Reuse C9.
- Verify current API and CORS behavior before choosing direct versus controlled transport;
  do not assume a mocked fetch test demonstrates browser connectivity.
- **Acceptance:** credential validation, wrong account, expired token, and permission
  failures are actionable. No deployment happens merely by entering a credential.

### V14-04 — Publish, observe, and retry

- Paths: `runtime/src/deploy/deploy-manager.ts`, Cloudflare Pages adapter, shared panel.
- Connect artifact upload and deployment creation to the UI, showing destination and
  explicit Publish action. Track upload/deployment status and final URL/error.
- Bound retries, reconcile uncertain network results, and preserve the previous working
  deployment. Provide history/link to the provider for rollback; do not invent automatic
  rollback guarantees or deploy user backend Workers in this milestone.
- **Acceptance:** A14 publishes F03 to an owned test project, verifies assets/routing,
  and retries a simulated interruption without reporting a false success.

### V14-05 — Complete documented delivery journeys

- Paths: public getting-started/product guides, templates, E2E, evidence.
- Walk through create→edit→test→preview→commit→publish on macOS and the certified iPad
  path. Explain network requirements, unsupported runtimes, and static-output limits.
- Include export/manual publication when an environment cannot authenticate or reach
  a provider; do not label that fallback an integrated publish success.
- **Acceptance:** a fresh user completes the documented path; real-service evidence
  references the commit/artifact and redacted result. Missing credentials remain a pending
  external test rather than a fabricated certification.

## Exit demonstration

Make a deliberate test fail, fix it, build, inspect output, publish, and open the URL
on another device. Change source afterward and show that the published artifact is
correctly identified as the earlier snapshot.
