# 0.2 — File integrity and recovery

Status: pending. Depends on 0.1 fixtures/CI/contracts. Pending physical runtime
validation does not prevent persistence fixes. Contracts: C2–C4.

**User outcome:** cloning, editing, and reopening cannot overwrite another project;
save failures remain visible and recoverable. Data safety comes before expansion.

## Ordered tasks

### V02-01 — Workspace identity and conservative migration

- Paths: `core/src/services/runtime.service.ts`, `core/src/db/vertex.db.ts`,
  and `packages/frontend/types/src`.
- Separate stable ID, display name, normalized origin, and storage identity. Register
  multiple workspaces while keeping one active. Stop keying storage by repository basename.
- Add a versioned migration that recognizes existing sessions/stores and preserves
  the source until completed. Ambiguous historical collisions require recovery/export;
  do not guess ownership or delete the original.
- **Acceptance:** F06 creates independent projects. Running migration/restart twice
  preserves contents without duplicate entries; migration failure preserves the source.

### V02-02 — Binary contract and coherent storage ownership

- Paths: `runtime/src/types/fs.types.ts`, `runtime/src/fs/*`, preview file mounting,
  and `deploy/adapters/base.ts`.
- Add explicit byte/text reads. Normalize paths once. Preserve bytes through copying,
  renaming, mounting, import/export, and publishing; migrate consumers incrementally.
- Use one shared adapter/event source per workspace rather than disconnected editor,
  terminal, and preview filesystem watchers. Test MemoryFS and real persistent storage.
- Clarify the legacy OPFSFS name/IndexedDB implementation without adding an OPFS migration.
- **Acceptance:** F01 PNG/font hashes survive rename/copy. Empty files, Unicode, and
  invalid paths have defined behavior and contract coverage.

### V02-03 — Staged clone and activation after success

- Paths: RuntimeService, GitClient, clone dialog, and a small coordinator if needed.
- Clone into new storage, validate repository/tree, then activate it. Keep the previous
  workspace and its write queue intact until success.
- Journal incomplete operations for restart cleanup/retry. Cancellation limits network
  work and prevents an obsolete clone result from becoming active.
- **Acceptance:** failure halfway, cancellation, and retry preserve the previous project.
  No destructive clear of existing data precedes success; callbacks retain workspace identity.

### V02-04 — Ordered writes and revision-aware confirmation

- Paths: web editor page/session service and a shared save coordinator in core.
- Extract debounce into a queue keyed by workspace/document/revision. Manual save waits
  for that revision; later edits remain dirty.
- Serialize rename/delete with writes. Rebind/cancel operations appropriately, update
  active document and descendant paths, and protect occupied destinations with explicit
  replacement plus a recoverable copy.
- **Acceptance:** edit→rename never recreates the old path; edit→delete never resurrects
  the file. Slow save plus further typing never marks new text clean. Write failure
  retains the buffer and offers retry/export.

### V02-05 — Durable drafts and concurrent browser tabs

- Paths: VertexDatabase, save coordinator, session bootstrap, `apps/web/src/pwa.ts`,
  and a small shared recovery UI.
- Persist drafts with workspace/document/revision/base identity, independent of
  sessionStorage. Recover by comparing, restoring, or exporting.
- Define durability acknowledgement and quota behavior. Beforeunload is supplementary,
  not a guarantee that async writes finish when the browser closes.
- Coordinate writers across tabs or make the second read-only. Handle crash takeover
  and divergent versions without silently choosing the last writer.
- **Acceptance:** abrupt termination recovers the last confirmed revision; closing a
  tab or replacing the app shell never deletes drafts. Completely unavailable storage
  is explained, and concurrent tabs cannot overwrite each other's edits silently.

### V02-06 — Make preservation a required integration gate

- Paths: browser E2E, FS/session tests, CI, and `evidence/0.2.md`.
- Implement A01/A02 and failure sequences from preceding tasks against real browser
  storage. Reload at defined interruption points, including migration/clone/rename.
- Cover incomplete journal, renamed folders with open children, occupied targets,
  and denied writes. Controlled timers supplement actual-browser coverage.
- **Acceptance:** regressions detect the previous destructive behavior and block web
  release. Document recovery of legacy stores.
