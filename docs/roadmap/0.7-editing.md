# 0.7 — Productive editing, navigation, and search

Status: pending. Depends on 0.6. Contracts: C3, C4, C8. Reuse CodeMirror commands
and the command registry rather than implementing a second text engine.

**User outcome:** navigate a project, edit efficiently, and make reviewed changes
across files using keyboard or touch.

## Ordered tasks

### V07-01 — Complete everyday editing commands

- Paths: editor-core configurator/bindings, shared editor, command registry.
- Expose undo/redo, indentation, comment toggle, line move/duplicate/delete, folding,
  bracket matching, multiple cursors, selection expansion, and document find/replace.
- Use CodeMirror extensions and commands; preserve C4 history and IME. Provide visible
  actions where keyboard combinations conflict with browser/OS behavior.
- **Acceptance:** a documented command table has working actions and regression
  coverage for edits/selection/undo. Read-only documents reject mutating commands.

### V07-02 — Quick open and navigation history

- Paths: workspace file index in core, palette/quick-open UI, document controller.
- Index paths incrementally with exclusions and cancellation. Add fuzzy quick open,
  recent files, go-to-line, and back/forward locations. Distinguish document history
  from browser navigation and from undo history.
- Rename/delete updates the index and navigation entries; switching workspace cancels
  the old index generation. Do not synchronously read every file body to list paths.
- **Acceptance:** F07 quick-open meets the calibrated budget and resolves duplicate
  basenames visibly. Back/forward restores document/selection after rename or reports
  a missing target without activating an unrelated file.

### V07-03 — Project search

- Paths: proposed search service/worker, shared search panel, filesystem contracts.
- Implement literal/case/whole-word search with include/exclude patterns; add regular
  expressions only with bounded execution and cancellation. Search dirty buffers as
  their current versions rather than stale disk text.
- Exclude binary, dependency, Git, and generated files by default; let the user inspect
  exclusions. Stream results with file/line/context and limits, avoiding a frozen UI.
- **Acceptance:** results open the correct range; F07 meets the budget, cancellation
  stops work, invalid regex yields a message, and stale results cannot cross workspaces.

### V07-04 — Previewed multi-file replacement

- Paths: search panel/service, document controller, C3 write coordinator/recovery.
- Show proposed file changes before applying. Revalidate source revisions before each
  update; abort or ask to recompute when a file changed after the search.
- Preserve a recovery snapshot and operation manifest. Apply through shared document
  operations; describe partial failures rather than claiming atomic cross-file writes.
- **Acceptance:** A07 covers dirty/open/closed files, write denial halfway, cancellation,
  and externally changed contents. Recovering the operation restores the right versions
  without overwriting newer edits silently.

### V07-05 — Preferences and two editor groups

- Paths: PreferencesService/ConfigService, layout, tabs, editor view ownership.
- Expose theme, font size, tab size, wrapping, line numbers, and keybindings through
  settings backed by C8 precedence. Support data-only project settings and basic
  EditorConfig behavior with documented precedence; unsupported keys are explicit.
- Add at most two editor groups with move/open-in-other-group, preserving one document
  identity and coherent shared edits. Adapt to one visible group on narrow screens.
- **Acceptance:** changing preferences keeps undo/focus; malformed config does not
  break startup. Editing a document shown twice converges, and closing one view keeps
  the other alive. Persistence does not restore unusable split sizes on a phone.

## Exit demonstration

Open a file by name, navigate between locations, edit with multiple cursors, search
the project, preview/apply replacements, and recover a deliberately failed operation.
Show the same document in two groups without creating two competing buffers.
