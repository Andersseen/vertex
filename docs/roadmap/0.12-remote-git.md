# 0.12 — Remote Git, authentication, and conflicts

Status: pending. Depends on 0.11 and validated D04/D08. Contracts: C3/C9/C10.
Support GitHub HTTPS first. Use owned test repositories for real remote evidence.

**User outcome:** bring a GitHub project into Vertex, push work back, and recover
from conflicting remote changes on desktop and supported browser/iPad environments.

## Ordered tasks

### V12-01 — Implement the validated transport boundary

- Paths: GitClient transport injection, native Git provider, proposed
  `packages/backend/gateway` if D04 requires it, and deployment documentation.
- Implement only approved GitHub transport routes/providers. Validate repository
  destination, redirects, methods, payload limits, timeout, cancellation, and authorization.
  CORS is an origin policy, not the sole authorization mechanism.
- Use Cloudflare for a required controlled gateway. Keep credentials/body contents out
  of logs and caches; do not forward credentials to arbitrary redirect destinations.
  No remote project execution or general URL proxy is introduced.
- **Acceptance:** allowed clone/fetch/push traffic succeeds; arbitrary URLs, forbidden
  redirects, and credential-bearing public-proxy requests fail safely. Document the
  actual infrastructure/account requirement and operator setup.

### V12-02 — Session authentication and credential lifecycle

- Paths: credential provider, clone/remote UI, native credential integration if used.
- Implement D08 session-token baseline with clear host/repository context, minimum
  required permissions, reauthentication, and forgetting credentials. Optional native
  persistence requires appropriate OS storage and an explicit user choice.
- Never put tokens in project config, clone URLs, terminal arguments, error output,
  browser storage, export archives, or preview environment.
- **Acceptance:** private clone and expired/revoked/wrong-permission failures have useful
  messages. Logout/forget clears session material. Log/URL/export inspection finds no token.

### V12-03 — Clone/open-link and fetch/push workflow

- Paths: transactional clone coordinator, Git service, branch/source-control UI.
- Integrate authenticated cloning with staging/recovery from 0.2. Explicit repository
  links open the intended flow instead of silently restoring another project.
- Add fetch, upstream selection, incoming/outgoing state, and non-forced push. Record
  completion accurately; retrying after uncertain network failure rechecks remote state.
- **Acceptance:** clone→edit→commit→push works in owned public/private repositories;
  a non-fast-forward push is explained and never resolved by automatic force.

### V12-04 — Pull and conflict state machine

- Paths: Git service/providers, operation journal, document/runtime coordination.
- First support safe fast-forward; then a documented merge workflow. Before mutation,
  synchronize source and protect dirty buffers. Keep a recoverable pre-operation state.
- Model fetching, preparing, merging, conflicts, resolved, completed, failed, and
  aborted. Detect interrupted operations on reopen rather than pretending the repo is clean.
- **Acceptance:** fast-forward updates open documents; divergent history enters an
  explicit conflict state. Network/write failure preserves pre-operation information;
  abort restores the intended state without deleting newer unrelated work.

### V12-05 — Conflict resolution UI

- Paths: shared merge/conflict panel, editor/diff views, Git operation coordinator.
- Show base/local/remote/result for text with accept-side and manual edit actions.
  Treat binary, add/add, modify/delete, and path conflicts explicitly; unsupported rare
  cases explain a safe export/external-resolution route rather than inventing a merge.
- Confirm resolved files, preserve copies, stage results, and complete/abort the merge
  through the operation state machine. Provide a usable inline iPad view.
- **Acceptance:** F05 conflicting text is resolved and committed; choosing a binary
  version preserves its bytes. Unresolved conflicts prevent completion and unsafe push.

### V12-06 — Network failure, credential, and recovery gate

- Paths: deterministic HTTP fixtures, gateway/native/browser tests, E2E, evidence.
- Cover offline, timeout, cancellation, 401/403, rate limiting, remote deletion, and
  process interruption during merge. Keep bounded retries and clear operation ownership.
- Run A12 against a disposable owned remote and record exact platform/versions. Tests
  without credentials must report remote certification pending, not silently pass it.
- **Acceptance:** complete iPad/macOS remote journey where certified, redacted evidence,
  and a recovery guide. No user token touches an uncontrolled public proxy.

## Exit demonstration

Clone a private owned repo, edit/commit/push, introduce a conflicting remote edit,
fetch/pull, inspect both versions, resolve, and push. Repeat the abort path and a
token-expiration failure without losing local work.
