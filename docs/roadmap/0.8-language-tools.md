# 0.8 — Project-aware JavaScript and TypeScript tooling

Status: pending. Depends on 0.7. Contracts: C3, C7, C8, C9. The existing
`TsLanguageService` is the starting point; its presence is not project-wide support.

**User outcome:** understand errors, discover symbols, navigate imports, refactor
names, and format code in a real JS/TS project without blocking typing.

## Ordered tasks

### V08-01 — Worker protocol and project model

- Paths: `runtime/src/lsp/ts-language-service.ts`, its tests, and
  `ui/src/lib/lsp/ts-lsp-extension.ts`; proposed worker entry/provider interface.
- Move costly TS work off the UI thread. Define request IDs, workspace/document
  versions, cancellation, disposal, loading/error states, and a bounded queue.
- Feed project sources, dirty overlays, create/rename/delete events, and tsconfig
  into one project service. Avoid reparsing the entire project on every keypress.
- **Acceptance:** delayed replies cannot affect a newer revision or another workspace;
  a worker crash permits retry while editing continues. F07 typing stays within budget.

### V08-02 — Standard libraries and module resolution

- Paths: TS host/provider, project indexing, browser asset/type loader.
- Supply pinned TypeScript standard/DOM libraries and resolve relative imports,
  compiler options, paths/baseUrl, JS checking, JSX/TSX, and declaration files.
- Resolve types from available project dependencies. Before installation, report
  missing dependency types accurately; an optional cache/downloader must pin versions,
  respect network failure, and never transmit private source for type inference.
- **Acceptance:** F02 resolves cross-file and typed-package symbols correctly. Missing
  packages produce useful diagnostics instead of fake globals. Changing tsconfig or
  a declaration updates the project without reloading Vertex.

### V08-03 — Completion, hover, diagnostics, and navigation

- Paths: shared TS extension, diagnostics model/panel, document navigation commands.
- Connect completion details/application edits, signatures, hover, go-to-definition,
  find references, and document symbols. Add a Problems panel with severity/source,
  file/line navigation, and cancellation of obsolete results.
- Use safe text rendering for diagnostic/hover content; support keyboard and tablet
  dismissal. Show indexing/loading distinctly from “no errors.”
- **Acceptance:** A08 navigates across project files and a typed dependency; selecting
  a diagnostic positions the correct document. Open/closed files share current results,
  and stale completion edits never corrupt a newer buffer.

### V08-04 — Safe symbol rename and common code actions

- Paths: language provider and shared multi-file edit coordinator from V07-04.
- Split into provider-result validation and UI/application subtasks if needed.
  Offer symbol rename, organize imports, and a bounded set of TS-supported fixes.
- Preview affected files for multi-file changes, verify revisions, preserve recovery,
  and apply through C3. Reject unsupported rename targets with a specific explanation.
- **Acceptance:** renaming an imported symbol updates references while preserving
  unrelated text; changed/read-only files prevent unsafe application. Recovery restores
  the operation without silently discarding edits made afterward.

### V08-05 — Formatting and linting

- Paths: `runtime/src/extras/format`, `runtime/src/extras/lint`, commands/preferences,
  diagnostics provider and tasks integration point.
- Integrate explicit format and optional format-on-save for JS/TS/JSX/TSX/JSON/HTML/CSS/
  Markdown. Preserve selection, revision safety, line endings, and a single undo step.
- Provide bounded built-in lint rules in browser workers; trusted project lint scripts
  are executed later through 0.9 tasks. Do not execute arbitrary ESLint/Prettier config
  in the workbench origin. Document supported data configuration and precedence.
- **Acceptance:** formatting an old revision never replaces new typing; invalid code/
  config leaves the document intact. Lint messages identify their provider and do not
  duplicate TypeScript diagnostics without explanation.

### V08-06 — Language scope, fallback, and interaction tests

- Paths: editor profiles, public docs, browser integration tests, `evidence/0.8.md`.
- Verify syntax/indentation for supporting HTML/CSS/JSON/Markdown. Document that advanced
  Angular-template/Vue/Svelte intelligence and non-JS language servers are outside scope.
- Test offline cached libraries, loading failures, large generated declarations,
  worker disposal, and switching projects repeatedly. Keep standalone editor's default
  compact profile independent from workbench-wide language services.
- **Acceptance:** A08 and performance checks pass on the declared matrix; no main-thread
  full-project TS analysis. The docs distinguish highlighting, semantic assistance,
  and ability to execute a project.

## Exit demonstration

In F02, import a dependency, complete a symbol, inspect its type, jump to definition,
rename a symbol across files, fix a diagnostic, and format. Repeat essential actions
on iPad while showing that typing remains responsive during indexing.
