# 0.1 — Verifiable foundation and platform feasibility

Status: pending. Entry: current repository. Exit: evidence and stable implementation
criteria. Follow [EXECUTION](EXECUTION.md), [CONTRACTS](CONTRACTS.md), and
[VALIDATION](VALIDATION.md).

**User outcome:** capabilities are described honestly and the team knows which
workflow can be certified on the owner's iPad. This minor does not build another IDE.

## Ordered tasks

### V01-01 — Freeze scope and record the baseline

- Paths: root/package scripts, roadmap documents, `docs/EDITOR_FOUNDATION.md`,
  `apps/web/playwright.config.ts`, and Tauri configuration.
- Inventory implemented/integrated/tested capabilities. Record installed versions
  and devices, including the owner's actual iPadOS. Preserve macOS-first scope.
- Run lint, types, tests, boundaries, web/editor builds, and native build where the
  toolchain exists. Separate existing failures from missing hardware/signing access.
- **Acceptance:** `evidence/0.1.md` records commit, commands, outcomes, concrete matrix,
  and unresolved decisions. A class's existence is not feature completion; current
  package numbers are not already-published roadmap milestones.

### V01-02 — Fixtures and a required browser smoke

- Paths: proposed `tests/fixtures/projects`, `apps/web/tests/e2e`, Playwright config,
  `.github/workflows/ci.yml`, and `test-setup.ts`.
- Prepare small reproducible F01/F02/F05/F06 fixtures and pinned F03/F04 projects.
  Serve Git fixtures locally rather than depending on mutable public repositories.
- Make a real open-editor/type/switch-tab smoke blocking for web deployment. Prepare
  A01 as the persistence regression added in 0.2; do not mask failures with mocks.
- **Acceptance:** breaking the smoke prevents application deployment; no credentials
  or public network are required. New integration tests do not load the global setup
  that turns Angular effects into no-ops; separate runner configuration as needed.

### V01-03 — Capability model and visible states

- Paths: `packages/frontend/types/src`, `core/src/services`, web app configuration,
  and preview-panel components.
- Introduce minimal C5 contracts. Probe disposable persistence writes/reads, secure
  context, and relevant runtime prerequisites. Avoid repeated initialization loops.
- Keep editing/export available when preview cannot boot. Report checking/unavailable
  states with specific reasons. Disable or identify unimplemented controls; do not
  implement the whole command palette in this task.
- **Acceptance:** storage-blocked/runtime-unavailable tests preserve the buffer and
  explain the limitation. User-agent matching does not determine capabilities.

### V01-04 — Early physical iPad experiment and execution-path decision

- Paths: `runtime/src/preview-wc-headless`, existing preview panel, `evidence/0.1.md`.
- Test F01–F04 on Chromium and physical iPad: boot, dependencies, Magic Keyboard
  input, preview, Safari tab switching, and resume. Record isolation, memory, script,
  and embedding limitations separately.
- If WebContainers cannot complete the TS case, test a bounded static esbuild path
  with F02. This experiment does not build a second general-purpose runtime.
- **Acceptance:** fixture/device matrix, redacted evidence, and a D05 decision. Without
  hardware, deliver an exact runnable procedure and leave physical validation pending;
  do not invent a pass.

### V01-05 — Establish transport feasibility before remote Git/publication

- Paths: `runtime/src/git/git-client.ts`, clone dialog, existing deploy adapters.
- Trace credentials and data flows. Block private credentials with the default public
  CORS proxy and explain the controlled-transport requirement.
- Test GitHub HTTPS transport, redirects, CORS, and authorization through a controlled
  test endpoint. Define a minimal gateway contract if required. Investigate publication
  with user-owned credentials without provisioning production infrastructure.
- **Acceptance:** D04/D08 have a viable proposal, risks, and external prerequisites;
  no token appears in commits/logs. Public-proxy credential protection has a test.

### V01-06 — Measure interaction and set performance budgets

- Paths: web tests, editor bundle-budget script, F07, and `evidence/0.1.md`.
- Measure editor-only and runtime-active costs separately, including TS loading and
  bundles. Record cold/warm runs, device, versions, method, and a repeatable command.
- Compare VALIDATION targets with evidence; explain any recalibration before enabling
  a gate. Record runtime distribution/service prerequisites without purchasing services.
- **Acceptance:** another contributor can reproduce results. No unsupported “faster
  than VS Code/Zed” statement. Proposed budgets remain clearly distinguished from measurements.

## Exit gate

Required smoke, baseline, and risk register; no default private-token forwarding to
a public proxy. D05 has physical evidence or an explicitly pending hardware dependency.
Independent data fixes may proceed; runtime commitments wait for the decision.
No extra languages, marketplace, or broad architectural rewrite.
