# 0.9 — Shared runtime, terminal, and tasks

Status: pending. Depends on 0.8 and a resolved D05 execution path. Contracts: C5/C6/C9.
The current custom command shell is a fallback, not proof of a Node terminal.

**User outcome:** install dependencies and run project scripts from a terminal/task
panel that operates on the same project as the editor.

## Ordered tasks

### V09-01 — Runtime owner and lifecycle state machine

- Paths: `runtime/src/preview-wc-headless`, core adapters, web PreviewSessionService,
  terminal backend contract, and native process provider from 0.4.
- Establish one active browser runtime owner with workspace/generation identity.
  Terminal/tasks/preview obtain that owner instead of independently booting containers.
- Define transitions, cancellation, progress, retry, and cleanup. Switching projects
  drains synchronization, stops owned processes, then activates a new generation.
- **Acceptance:** concurrent start requests produce one boot; start→cancel→retry does
  not resurrect old callbacks. Browser runtime constraints are checked against installed APIs.

### V09-02 — Native interactive terminal

- Paths: `core/src/terminal`, xterm panel, native `terminal.rs` and adapter registration.
- Wire PTY input/output/resize, shell cwd, Ctrl-C, exit status, and disposal through the
  shared contract. Preserve incremental decoding and child cleanup established in 0.4.
- Support multiple terminal sessions with explicit limits, names, and active workspace;
  application lifecycle owns them rather than whether a panel is visible.
- **Acceptance:** hide/show terminal preserves a running task; close terminal actually
  stops its process tree. Paths with spaces and Unicode input/output work in the installed app.

### V09-03 — Browser processes and package installation

- Paths: WebContainerRunner, package-manager detection, browser terminal adapter.
- Connect an actual supported shell/process stream where capability exists. Certify npm
  with pinned public-package fixtures; respect lockfiles and distinguish install from
  clean reproducible install. Do not globally install Bun because a bun lockfile exists.
- Report unsupported managers/native modules/private-registry requirements explicitly.
  Bound logs, installation retries, and cancellation; retain exit codes and elapsed time.
- **Acceptance:** F03 installs/runs and a broken dependency reports a terminal failure
  without deleting source. Limited fallback mode never advertises arbitrary Node commands.

### V09-04 — Editor/storage to runtime synchronization

- Paths: shared operation stream, runtime file mounting, proposed sync coordinator.
- Mount byte-preserving snapshot, then apply ordered create/edit/rename/delete events
  with origin/revision IDs. Maintain exclusions for Git, dependencies, and generated output.
- Introduce barriers for commands that require current source. Avoid feedback loops
  and writes into a disposed workspace generation.
- **Acceptance:** edit/create/rename/delete from UI appear in runtime reads; binary assets
  match. A queued edit cannot land in the next project after switching.

### V09-05 — Runtime changes back to documents and persistence

- Paths: sync coordinator, document controller, provider filesystem observation.
- Observe or reconcile terminal-generated source/manifests/lockfiles. Keep dependencies
  and output out of source persistence unless intentionally exported. Document API
  observation gaps and a bounded reconciliation strategy.
- For a dirty buffer versus external runtime edit, preserve base/local/external versions
  and offer resolution. A package install that changes a lockfile must survive restart.
- **Acceptance:** A09 uses terminal commands to create/edit/delete a file and observes
  editor/explorer/persistence convergence. Concurrent edits surface a conflict, not data loss.

### V09-06 — Tasks and execution trust

- Paths: project script reader, shared task panel/commands, runtime/native providers.
- List package scripts as data and offer run/stop/retry with state, cwd, logs, and result.
  Execution or package installation requires a deliberate action and project trust.
- A clean task result belongs to a specific source snapshot; subsequent edits make it
  stale. Pass user-chosen project environment only to that project; never pass IDE credentials.
- **Acceptance:** opening a malicious fixture executes nothing. A failing/hanging script
  is diagnosable/cancelable. Two task names do not overwrite each other's state.

### V09-07 — Lifecycle and process regression gate

- Paths: provider contract tests, browser/native smoke, `evidence/0.9.md`.
- Exercise failed boot/install/spawn, partial output, rapid workspace switching, panel
  remount, cancellation, and thirty start/stop cycles. Check owned listeners/timers/processes.
- Document terminal differences by platform, including browser Git commands when `.git`
  is deliberately outside the execution mirror; Git UI owns repository operations.
- **Acceptance:** A09 passes with real native/WebContainer paths where certified;
  unsupported iPad runtime follows D05 without claiming shell parity.

## Exit demonstration

Install F03, run a script, edit a source file from terminal, observe the editor update,
edit from the editor, read it from terminal, then stop everything and reopen the project.
Both directions preserve revisions and lockfile changes.
