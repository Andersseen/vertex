# 0.11 — Local Git and trustworthy change review

Status: pending. Depends on 0.10. Contracts: C2/C3/C10. Remote authentication and
network synchronization are deliberately delivered in 0.12.

**User outcome:** inspect exactly what changed, choose files to commit, preserve
history, and switch branches without losing unsaved work.

## Ordered tasks

### V11-01 — Repository service and correct status model

- Paths: `runtime/src/git/git-client.ts`, Git types/tests, native adapter, core controller.
- Expose repository root, branch/detached state, HEAD/index/working-tree status, and
  operation lock through a common service. Native provider may use installed Git;
  browser provider extends isomorphic-git behind the same contract.
- Do not flatten staged and unstaged changes into one exclusive bucket. Refresh after
  coordinated saves, runtime reconciliation, Git mutation, and external changes.
- **Acceptance:** F05 tests staged-only, unstaged-only, both, additions, deletions,
  ignored/untracked files, and unborn repositories against real Git state.

### V11-02 — Source-control panel and diffs

- Paths: shared source-control panel, command registry, editor/diff view.
- Display staged/unstaged lists, actual branch, and diff choice between working tree,
  index, and HEAD. Use a maintained diff primitive where appropriate; keep it out of
  the standalone editor's default bundle.
- Handle empty/large/binary/deleted files and new files explicitly. Diff navigation
  opens source; a dirty buffer must be saved or identified as unsaved in the comparison.
- **Acceptance:** visible diff matches the selected comparison and line endings;
  binary assets are never decoded and saved as text. Phone/tablet can read the diff
  in an inline layout without requiring a wide side-by-side view.

### V11-03 — Stage, unstage, discard, and commit

- Paths: Git providers/controller, write coordinator, source-control UI.
- Support file-level stage/unstage and commits with identity/message validation.
  Partial-hunk staging can wait until after 1.0. Handle staged deletions correctly.
- Discard is an explicit destructive action with reviewed targets and recoverable
  copies. Coordinate dirty buffers and preserve changes not included in the commit.
- **Acceptance:** commit contains only selected index changes; cancellation or provider
  failure preserves index/working data. Discard never affects unrelated dirty documents.

### V11-04 — Local branches and history

- Paths: branch/history UI, Git providers, document reconciliation.
- List/create/switch local branches and show recent commits with affected files.
  Protect working changes before checkout; offer save/cancel and explain conflicts.
- Reconcile open documents after a successful branch change without inserting checkout
  contents into the wrong undo history. Show deleted-on-branch documents safely.
- **Acceptance:** A11, unborn/detached states, branch with deleted file, and checkout
  blocked by local changes. No automatic reset/force is used as a recovery shortcut.

### V11-05 — Cross-provider contract tests and gitignore behavior

- Paths: F05 setup, provider contract tests, E2E, `evidence/0.11.md`.
- Run equivalent staged/commit/branch scenarios against browser storage and native Git.
  Test nested gitignore, path normalization, Unicode, and case-sensitive distinctions.
- Validate serialized Git operations against concurrent editor autosave and runtime
  writes. Larger repositories produce progress/cancellation where supported.
- **Acceptance:** UI results match repository inspection; no fake fixed branch/status
  remains. A01–A11 relevant regressions pass and destructive actions have recovery evidence.

## Exit demonstration

Modify two files, stage one, inspect both diffs, commit only the staged change, create
a branch, switch safely, and inspect history. Repeat without any network connection.
