# 0.5 — Project creation and organization

Status: pending. Depends on 0.4. Contracts: C2–C5. Build project workflows on the
reliable filesystem rather than bypassing its coordinator.

**User outcome:** start without GitHub, import a project, organize its files, and
export a complete copy from browser or macOS.

## Ordered tasks

### V05-01 — Welcome screen, recent projects, and safe switching

- Paths: web routes/landing/editor, shared workspace controller, desktop bootstrap,
  and VertexDatabase.
- Offer create/import/clone/open-recent according to capability. An explicit clone
  URL must not disappear behind automatic restoration of the previous session.
- Switching coordinates dirty documents and runtime shutdown. Show origin/name/last
  opened; distinguish removing a recent entry from deleting project data.
- **Acceptance:** same-name projects are distinguishable; tabs, terminal, and stale
  search results do not leak between projects. Data deletion is an explicit action.

### V05-02 — Templates and project creation

- Paths: proposed data-only project template catalog and shared creation UI.
- Provide static HTML/CSS/JS, simple TS, Vite TS, React TSX, and Angular CLI templates
  according to the support matrix. Pin dependencies/lockfiles and stage validated creation.
- Creating does not install or execute scripts. Explain the available next step.
  Templates stay small and contain no secrets, tracking, or unnecessary integrations.
- **Acceptance:** bundled templates can be created offline with expected contents;
  cancellation leaves no partially active project. Build certification follows in 0.10.

### V05-03 — Byte-preserving import and export

- Paths: project services, FS adapters, and shared file-picker UI.
- Import files/folders where supported and ZIP as a common fallback. Validate paths,
  duplicates, decompressed size, and resource limits.
- Export a consistent snapshot, excluding dependencies/regenerable output by default.
  Explain sensitive files included; include Git history only through an explicit option
  where supported. Preserve binary contents and empty folders.
- **Acceptance:** A05, traversal ZIP entries, Unicode, and occupied targets are covered.
  Failed import preserves the active project. Test export through the actual iPad Files flow.

### V05-04 — Complete explorer and correct operation targets

- Paths: shared sidebar, `core/src/services/file-tree.ts`, extracted file operations.
- Create inside the selected node; rename/move/delete the context-menu target rather
  than accidentally acting on the active editor. Protect occupied destinations.
- Synchronize tree/tabs/descendant paths while preserving focus and expansion. Exclude
  expensive directories from indexing without preventing explicit access to allowed files.
- **Acceptance:** new `src/new.ts` appears immediately with correct language; moving
  an open folder preserves documents; delete with autosave satisfies C3. Keyboard
  navigation reaches all essential explorer actions.

### V05-05 — Real file metadata and bounded editing

- Paths: document metadata, empty/editor states, statusbar, and file information UI.
- Show actual path, language, supported encoding/line endings, and save status.
  Detect binary/oversized files before loading them as ordinary text.
- Offer safe image display/download and a documented large-file mode. Loading a large
  file remains cancelable without freezing the entire workbench.
- **Acceptance:** statusbar reflects JSON/TS changes; binary contents cannot be saved
  through text decoding; canceling large-file load returns to the previous document.

## Exit demonstration

Create TS project, add/move folders and files, export ZIP, import as another project,
and compare content on macOS/iPad. Organizing files does not depend on implementing
the later runtime or remote Git milestones.
