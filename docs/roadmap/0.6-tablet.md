# 0.6 — Tablet, mobile, and keyboard interaction

Status: pending. Depends on 0.5 and physical evidence from V01-04. Contracts: C4/C8.

**User outcome:** iPad with Magic Keyboard is a primary working environment, with
touch as a usable alternative and sufficient visible editing space.

## Ordered tasks

### V06-01 — Shared commands and command palette

- Paths: proposed command registry in core, shared layout/menus/sidebar, palette in UI.
- Register existing actions with ID, label, context, availability, and shortcuts.
  Menus/buttons use the same actions. Build searchable palette using existing headless
  overlays/lists, restoring focus when dismissed.
- Handle conflicts with inputs, terminal, IME, browser, and OS. Every essential action
  has a visible route even when its preferred shortcut is reserved.
- **Acceptance:** create/save/toggle-panel through palette and menu behave identically;
  disabled commands cannot run; composing an accent never triggers a workbench action.

### V06-02 — Adaptive layout and panels

- Paths: main-layout, tabs/sidebar/bottom-panel, and ide-ui tokens.
- Define desktop splits, collapsible tablet panels, and a single primary phone surface.
  Restore preferences without pushing the editor offscreen after a viewport change.
- Support safe areas, dynamic viewport, rotation, and reduced iPad windows. Provide
  compact toolbars and alternatives to hover or mandatory dragging.
- **Acceptance:** at 390/768/1024 px essential controls remain reachable; rotation
  preserves text/focus. Opening/closing terminal still leaves a usable editor.

### V06-03 — Keyboard input, selection, and composition

- Paths: editor-core bindings, shared editor, overlays, and styles.
- Test Magic Keyboard, virtual keyboard, trackpad/touch selection, clipboard, word/line
  navigation, indentation, Spanish dead keys, and IME composition.
- Preserve native selection gestures instead of simulating the entire editor through
  pointer handlers. Provide an accessible way to leave the editor using the keyboard.
- **Acceptance:** composition/copy/paste/undo never duplicate or lose characters;
  virtual keyboard does not persistently cover the cursor. Record physical evidence
  alongside automated regressions in `evidence/0.6.md`.

### V06-04 — Focus, accessibility, and feedback

- Paths: interactive ide-ui components, palette, tree, tabs, and notifications.
- Label icon actions/selection/errors; restore focus after dialogs and use predictable
  modal navigation. Target 44 px primary touch actions and suitable contrast.
- Run automated accessibility checks and VoiceOver; announce useful completion/failure
  without reading every progress tick or editor keystroke.
- **Acceptance:** keyboard and VoiceOver can open/edit/save/export. Essential actions
  never depend solely on color or hover.

### V06-05 — iPad suspension and Home Screen web app

- Paths: session/recovery, `apps/web/src/pwa.ts`, service worker, and manifest.
- Test backgrounding, suspension, rotation, and return. Runtime may die; source data
  persists and restart is offered. Recheck storage on resume.
- Validate Home Screen installation independently and document observed storage
  boundaries rather than assuming Safari and installed web app always share data.
- **Acceptance:** A06 passes ten background/resume cycles without reload loops or lost
  confirmed saves. PWA limitations remain visible in the support matrix.

## Exit gate

The owner completes a 30-minute physical iPad session editing/organizing a project.
Record friction and fix blockers to that basic workflow. Responsive screenshots or
Playwright viewports do not replace this evidence.
