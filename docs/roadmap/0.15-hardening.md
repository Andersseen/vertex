# 0.15 — Hardening and distributable beta

Status: pending. Depends on 0.14. Feature development is complete for the defined
scope; this milestone closes measured reliability, performance, and delivery gaps.

**User outcome:** Vertex remains responsive during ordinary work, recovers across
updates/failures, and can be installed from an identifiable macOS artifact.

## Ordered tasks

### V15-01 — Performance budgets and resource ownership

- Paths: baseline harness/F07, editor/document indexing, TS worker, preview/terminal
  lifecycle, bundle configuration; change only demonstrated bottlenecks.
- Repeat 0.1 measurements on reference devices. Profile misses, separate editor from
  runtime/network costs, and fix the largest measured cause before remeasuring.
- Check thirty open/close/project/preview cycles for leaked workers, listeners, process
  handles, blob URLs, views, and unbounded log/draft caches. Document eviction policies
  that never remove the only unsaved copy.
- **Acceptance:** calibrated budgets pass or an explicit evidence-based scope/budget
  decision is recorded before beta. No unsubstantiated comparison to competing editors.

### V15-02 — Offline editing and safe PWA updates

- Paths: web PWA bootstrap/service worker, asset caching, storage/session recovery.
- Cache the application resources required for already-opened project editing and
  offer an update at a safe save boundary. Separate shell caches from source/draft data.
- Handle stale chunks, failed updates, disconnected startup, and cache/storage denial
  without reload loops. Explain that new installs/dependencies/Git/publish require network.
- **Acceptance:** A15 preserves confirmed source/drafts across offline reload and
  interrupted shell update. A cache cleanup cannot erase project stores or other apps'
  unrelated caches/service workers on the same origin.

### V15-03 — Migration and recovery fault matrix

- Paths: schema migrations, journal/recovery coordinator, deterministic fault tests.
- Test upgrade from the pre-roadmap schema and each released compatible schema.
  Inject failure before/after each commit point and repeat recovery twice.
- Provide export/recovery instructions and a version compatibility policy. Prevent an
  older application from silently rewriting a newer incompatible data schema.
- **Acceptance:** repeated recovery is idempotent; original data remains recoverable
  after quota/write failures. Downgrade limitations are explicit and tested where supported.

### V15-04 — Trust-boundary and accessibility review

- Paths: gateway, preview/embedding, native capabilities, archive import/export,
  credential providers, critical shared UI.
- Re-run hostile fixtures for path traversal/symlinks, forged messages, terminal output,
  executable configuration, secret exposure, and unauthorized native IPC.
- Recheck VoiceOver, contrast, focus, IME, keyboard conflicts, touch targets, and iPad
  virtual-keyboard behavior after all feature panels have landed.
- **Acceptance:** no unresolved credential/native-privilege/data-loss finding; critical
  journeys remain accessible. Record exact tests/findings/fixes rather than “security reviewed.”

### V15-05 — Reproducible macOS and editor release artifacts

- Paths: desktop Tauri config/build scripts, CI release configuration, web-editor release
  workflow/installers, release manifests and documentation.
- Build macOS Apple Silicon from a clean checkout, prepare signing/notarization and
  checksums, and test installation from the delivered artifact. Keep identities/secrets
  external. Create immutable editor bundles/types and versioned release notes.
- Implement guided manual update for D14, preserving settings/projects and explaining
  recovery/downgrade policy. Do not add silent background updating as a side project.
- **Acceptance:** a clean Mac launches the actual distributed signed artifact without
  monorepo dev dependencies. Missing owner signing credentials are an explicit release
  blocker, not an excuse to mark notarization complete.

### V15-06 — Support matrix and release evidence package

- Paths: public docs, compatibility/performance reports, `evidence/0.15.md`.
- Freeze exact supported OS/browser/template/toolchain versions and known limitations.
  Check setup/recovery/upgrade instructions against the built artifacts.
- Record external service requirements, token lifecycle, runtime distribution conditions,
  and reproducible developer commands. Do not publish private telemetry by default.
- **Acceptance:** artifact manifest ties versions/checksums/commit/tests together;
  A01–A15 applicable checks pass. Windows/Linux and uncertified runtimes remain explicitly
  outside the stable claim.

## Exit gate

A feature-complete beta artifact, recovery documentation, measured budgets, and
identified support matrix. Real signing/hardware/provider checks must have evidence;
remaining external blockers stay visible for release management.
