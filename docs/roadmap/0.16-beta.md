# 0.16 — Real-project beta and release candidates

Status: pending. Depends on 0.15. This milestone validates usefulness with complete
projects and fixes defects; it does not add another product surface.

**User outcome:** the owner can choose Vertex for a supported real web project and
finish the work without escaping to another editor for every essential operation.

## Ordered tasks

### V16-01 — Select representative real projects and test sessions

- Paths: `docs/roadmap/evidence/0.16.md`, issue templates, fixture matrix references.
- Select an owned small TS website, a medium Vite/React project, and an Angular project
  for macOS. Record versions, size, workflow, and permission to use any shared artifacts.
- Schedule owner sessions on macOS and physical iPad; observe creation/opening, editing,
  navigation, diagnostics, runtime, Git, recovery, and publication where supported.
- **Acceptance:** each session has concrete tasks, duration, environment, outcome, and
  friction report. Do not claim complete daily-use validation from a brief demo video.

### V16-02 — Fix workflow blockers and reproducible regressions

- Paths: only components identified by observed defects, associated regression tests.
- Triage by impact: data/credential failures, blocked core workflow, serious usability,
  then polish. Give each fix a small task ID linked to its source milestone/contract.
- Reproduce before fixing where feasible; add meaningful protection for data/concurrency
  failures. Avoid broad cleanup or architectural rewrites during beta.
- **Acceptance:** observed blockers have a retested outcome on the affected device;
  resolving an issue means the original user scenario now succeeds.

### V16-03 — Release candidate upgrade and distribution rehearsal

- Paths: release CI/artifacts, upgrade/recovery docs, evidence package.
- Produce versioned release candidates from identified commits; install/update the
  actual macOS artifact and hosted browser/editor artifacts.
- Rehearse interrupted update, unavailable gateway/provider, storage recovery, and
  returning from iPad suspension. Verify published docs match the candidate's behavior.
- **Acceptance:** candidate identity is reproducible, no unknown artifact rebuild occurs
  after testing, and manual/provider checks refer to that candidate or a documented
  equivalent code path unchanged since its evidence.

### V16-04 — Freeze the 1.0 acceptance packet

- Paths: evidence files, support matrix, changelog, known issues, 1.0 checklist.
- Review A01–A16 and every confirmed product commitment. Classify unresolved items as
  release blockers or non-blocking limitations with a user-visible workaround.
- Blocking: silent data loss, credential/native privilege exposure, broken certified
  primary workflow, missing required artifact/signing, or absent physical iPad evidence.
- **Acceptance:** owner/reviewer can trace each claim to evidence. No remaining blocker
  is relabeled as a limitation merely to reach the version number. Optional post-1.0
  work is separated from obligations still required to launch.

## Exit gate

At least the defined macOS and iPad real-project journeys complete on the release
candidate, required checks are reviewed, and the 1.0 acceptance packet is ready.
If a primary workflow fails, continue fixing within beta rather than expanding scope.
