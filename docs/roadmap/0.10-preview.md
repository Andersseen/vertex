# 0.10 — Live preview, builds, and application diagnostics

Status: pending. Depends on 0.9. Contracts: C5/C6/C9/C12. Extend the existing
Bundler and WebContainer preview rather than creating unrelated execution paths.

**User outcome:** see source edits reflected in the running application, understand
failures, and produce a known build artifact.

## Ordered tasks

### V10-01 — Shared dev-server workflow

- Paths: preview session/panel, runtime owner, task providers, script detection.
- Start a chosen or detected dev script through the shared runtime; show selected
  command, state, ready URL, logs, timeout, and stop/retry. Respect failed process exits
  instead of waiting only for a timeout. Track the owned server, not any emitted URL.
- Bind/remount iframe without restarting an unrelated process. Use supported cross-origin
  reload behavior rather than accessing another origin's location directly.
- **Acceptance:** A10 shows an edited source change; panel hide/show preserves the
  server, and stop/restart leaves no stale port/listener. Missing dev script is actionable.

### V10-02 — Bounded static preview path

- Paths: existing Bundler/plugins and a static preview provider behind C5/C6.
- Deliver the D05-approved F01/F02 subset with explicit supported imports/assets/options.
  Preserve JS/TS, CSS, and binary assets; avoid claiming arbitrary Vite/Angular configs work.
- Rebuild/update on source changes with cancellation and source snapshot identity.
  Pin/cache dependency resolution where used and explain offline cache misses.
- **Acceptance:** certified TS fixture runs on target iPad when this is its chosen path;
  unsupported config produces a clear limitation without silent framework substitution.

### V10-03 — Preview isolation and host boundary

- Paths: iframe binder, preview route/origin configuration, native webview permissions,
  and preview messaging protocol.
- Isolate project code from workbench storage, credentials, and Tauri IPC. Define
  sandbox/origin policy for native URLs, WebContainers, and static preview separately.
- Validate message sender/schema/size and dispose channels. Handle navigation/popups
  deliberately. Do not use same-origin executable HTML with full host privileges.
- **Acceptance:** hostile fixture cannot read workbench data or invoke native commands;
  valid app scripts/forms/assets still work. Forged postMessage events are ignored.

### V10-04 — Console and useful error navigation

- Paths: preview error/log bridge, shared console/Problems panel, source navigation.
- Capture build errors, runtime exceptions, rejected promises, and bounded console
  output for certified providers. Sanitize display and throttle excessive messages.
- Map supported stacks to source with sourcemaps; disclose unmapped/third-party frames.
  Console works on iPad without requiring desktop DevTools.
- **Acceptance:** a deliberate F03 error opens the right source location; a logging
  loop does not freeze the IDE. Preview logs cannot inject HTML or masquerade as host events.

### V10-05 — Build artifacts and framework certification

- Paths: task/build providers, Bundler, output extraction, template catalog.
- Run the project's real build script where a process runtime exists. Keep the bounded
  static builder a separately labeled provider rather than silently aliasing npm build.
- Record successful artifact snapshot, file manifest/hashes, output directory, and
  errors. Respect configured output directories; do not assume every project uses dist.
- **Acceptance:** F01–F03 produce valid artifacts with assets and navigation; F04 passes
  on macOS. Browser/iPad Angular status follows actual evidence. Failed builds cannot
  supply a fresh success artifact, and newer edits make earlier artifacts visibly stale.

### V10-06 — End-to-end preview matrix

- Paths: E2E/provider contract tests, `evidence/0.10.md`, public capability docs.
- Test install→run→edit→update→build, source rename/delete, network failure, dependencies
  missing, restart after failure, and iPad background recovery. Distinguish live HMR
  from full reload when describing each provider.
- **Acceptance:** A10 and isolation checks pass; each certified template has recorded
  platform/runtime/version. Unsupported projects remain editable/exportable.

## Exit demonstration

Create a certified TS project, render an asset, edit code/CSS, diagnose and fix a
runtime error, then build. Repeat the promised iPad workflow and show the exact
artifact associated with the source snapshot.
